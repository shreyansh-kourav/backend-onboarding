# Git Fundamentals

Git is a content-addressed store of **snapshots**. Everything else — branches, tags, `HEAD` — is a pointer to one of those snapshots. Once that clicks, most commands stop being magic.

## The three areas

```text
working tree            staging area (index)          repository
    |                          |                          |
    |  git add <file>  -------> |  git commit -m "..." --> |
    |                          |                          |
    | <----- git restore --staged <file>                  |
    | <----- git restore <file> (discard changes)         |
```

| Area | What lives there |
|---|---|
| Working tree | The files as they are on disk right now |
| Index / staging | Exactly what the next commit will contain |
| Repository (`HEAD`) | The last commit; immutable once written |

`git status` reports the difference between all three. Read it as: "unstaged changes" = working tree vs index; "changes to be committed" = index vs `HEAD`.

## The everyday loop

```bash
git status                     # what changed, in which area
git diff                       # working tree vs index (unstaged)
git diff --staged              # index vs HEAD (what you're about to commit)
git add app/main.py            # stage one file
git add -p                     # stage hunk by hunk — the habit worth building
git add -A                     # stage everything, including deletions
git commit -m "feat: add health endpoint"
git log --oneline --graph -10
```

`git add -p` is how you keep commits coherent when you've touched three unrelated things in one sitting.

## Undo, by intent

| I want to… | Command | Touches history? |
|---|---|---|
| Discard changes in a file | `git restore file.py` | No |
| Unstage a file (keep the edits) | `git restore --staged file.py` | No |
| Fix the last commit's message or contents | `git commit --amend` | Rewrites the last commit — **never after pushing** |
| Undo a pushed commit, safely | `git revert <sha>` | Adds a new commit that reverses it |
| Move my branch back, keep the changes staged | `git reset --soft HEAD~1` | Rewrites local history |
| Move back, keep changes unstaged | `git reset HEAD~1` (`--mixed`, default) | Rewrites local history |
| Move back and **destroy** the changes | `git reset --hard HEAD~1` | Rewrites local history; work is gone |

`revert` is the only one that's safe on a shared branch: it doesn't rewrite anything other people already have. `reset` and `amend` are local-history surgery.

The safety net for any of these going wrong:

```bash
git reflog          # every position HEAD has held, including "lost" commits
git reset --hard HEAD@{2}
```

`reflog` entries survive for ~90 days. A commit you reset away is still reachable from there.

## `.gitignore`

```gitignore
.venv/
__pycache__/
.env
*.log
```

- Ignore rules apply to **untracked** files only. A file committed before the rule existed stays tracked:
  ```bash
  git rm --cached .env      # stop tracking, keep on disk
  ```
- Check which rule is responsible:
  ```bash
  git check-ignore -v .env
  ```
- `.env.example` alongside `.env` in the ignore list needs a negation, and the negation must come after:
  ```gitignore
  .env
  .env.*
  !.env.example
  ```
- `.gitignore` is not access control. Anything committed stays in history, and secrets committed once must be **rotated**, not just deleted.

## Branches and merges

```bash
git switch -c feat/upload               # create and switch
git switch main                          # switch back
git merge feat/upload                    # merge into current branch
git branch -d feat/upload                # delete after merge
git branch -vv                           # local branches + upstream + last commit
```

A merge is **fast-forward** when `main` hasn't moved since the branch started — the pointer just slides forward, no merge commit. Otherwise Git creates a merge commit with two parents.

### Conflicts

```text
<<<<<<< HEAD
timeout = 30
=======
timeout = 60
>>>>>>> feat/timeouts
```

`HEAD` is your current branch; the other side is what you're merging in. Resolution loop:

```bash
git status                       # lists "both modified" files
# edit the file: pick one side, the other, or neither; delete the markers
git add <file>
git commit                       # completes the merge
git merge --abort                # or bail out entirely
```

Conflict markers are just text — but committing them accidentally is a real bug class, so search before committing: `grep -rn "<<<<<<<" .`

## Remotes

```bash
git remote -v
git remote add origin git@github.com:user/repo.git
git push -u origin main          # first push, sets upstream
git fetch origin                 # download refs, change nothing locally
git pull                         # fetch + merge
git pull --rebase                # fetch + replay your commits on top
```

- **`fetch` is always safe** — it updates remote-tracking refs only. `pull` is fetch plus a merge, so it can create conflicts.
- `git push --force` overwrites the remote and can erase teammates' commits. `git push --force-with-lease` refuses if the remote moved since your last fetch — use that if you must rewrite.
- Never `--force` a shared branch. Revert instead.

## Commit hygiene

- **One idea per commit.** "Fix login" not "login + formatting + dependency bump".
- **Message states why, not what.** The diff already shows what.
- **Prefix by area** so history is scannable: `feat(api):`, `fix(auth):`, `docs(day-2):`, `test:`, `ci:`.
- **Never commit** `.env`, credentials, `.venv/`, or generated binaries.
- `git log --oneline` should read like a changelog. If it doesn't, the commits are too coarse.

## Detached HEAD

`git checkout <sha>` (or checking out a tag) moves `HEAD` to a commit without a branch. New commits there belong to no branch and are easy to lose.

```bash
git switch -c rescue        # make the work a real branch
git switch main             # or just abandon it
```

## Quick reference

| Task | Command |
|---|---|
| What did I change? | `git status` / `git diff` |
| Stage selectively | `git add -p` |
| What's in the next commit? | `git diff --staged` |
| Who last touched this line? | `git blame -L 40,60 file.py` |
| What changed in a commit? | `git show <sha>` |
| Find a commit by message | `git log --grep="upload"` |
| Recover a lost commit | `git reflog` |
| Stop tracking a file | `git rm --cached <file>` |
