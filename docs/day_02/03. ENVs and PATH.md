## Environment variables

Key-value strings that the OS attaches to every process. A program reads them at runtime, so config (ports, API keys, mode) lives outside the code.

```bash
echo $HOME        # read one
env               # list all
```

A child process inherits a **copy** of its parent's variables. Changes it makes never flow back up.

## `PATH`

A colon-separated list of directories the shell searches, in order, when you type a command.

```bash
echo $PATH        # /usr/local/bin:/usr/bin:/bin
which python3     # shows which directory won
```

- First match wins, so order matters.
- "command not found" usually means the directory isn't in `PATH`.
- Activating a venv puts `.venv/bin` at the front of `PATH`, which is why `python` suddenly means the venv's Python.
- Add a directory with `export PATH="$HOME/bin:$PATH"`. Keep the `:$PATH` at the end, or you replace the whole list and break most commands.

## `export`

```bash
PORT=3000            # shell variable: only this shell sees it
export PORT=3000     # environment variable: child processes inherit it
```

```bash
PORT=3000
python3 -c "import os; print(os.getenv('PORT'))"   # None
export PORT=3000
python3 -c "import os; print(os.getenv('PORT'))"   # 3000
```

Exports last only for that terminal session. To persist them, put them in `~/.bashrc` or `~/.zshrc`, or in a project `.env`.

## `.env`

A plain text file of `KEY=value` lines, one per setting, kept in the project folder:

```
ANTHROPIC_API_KEY=sk-...
PORT=3000
```

The shell doesn't read it automatically. Your app loads it with a library (`python-dotenv`, or pydantic-settings in FastAPI), or you load it manually with `set -a; source .env; set +a`.

**Quick checks before you commit:**

```bash
git status                       # is .env listed? it shouldn't be
git check-ignore -v .env         # confirms which rule ignores it
git diff --staged                # read what you're about to commit
```
